# Flujo de trabajo

- Al finalizar cada etapa, crear una rama de trabajo, realizar los commits y abrir
  un pull request con los cambios de esa etapa. No dejar una etapa terminada
  únicamente como cambios locales sin commit.
- El PR debe explicar qué se implementó, cómo se verificó y qué queda pendiente.
- No hacer merge del PR sin una indicación del usuario.
- Si falta acceso al remoto, conservar los commits locales y comunicar el
  impedimento y el paso necesario para publicar el PR.
